## 1. 项目背景

**NodeSeek** 是一个中文技术社区论坛（VPS / 主机 / 建站 / 折腾），信息密度高、更新极快——
首页帖子的"最后回复时间"经常是 `1s ago`、`12s ago`。用户是重度、高频、碎片化使用。

本项目是它的**非官方开源 Android 客户端**。官方只有网页版，移动端体验一般；社区已有一个 iOS 客户端
和一个 React Native 客户端，本项目是原生 Kotlin + Jetpack Compose 实现。

**当时状态（历史快照）**：功能骨架仅覆盖帖子列表、详情、原生富文本和深色模式，视觉接近 Compose 默认样式。
后续 M3 设计、二级页面与批次 F 已落地，当前状态不要从本段推断。

### 关键技术约束（会影响设计决策，请务必读）

| 约束 | 设计含义 |
|---|---|
| 站点无公开 API，列表/详情靠抓 HTML | 拿不到结构化的"热度分""标签""摘要"，**不要设计依赖这些数据的组件** |
| 正文是服务端渲染的 Markdown | 正文可能包含：段落、图片、行内表情、代码块、引用、有序/无序列表、表格、行内链接 |
| 站点前端会改版 | 组件要能容忍某个字段缺失（比如版块标签、浏览数拿不到时不能塌陷） |
| 全站在 Cloudflare 后面 | 需要一个"人机验证"状态屏，用户要在内置浏览器里过验证 |
| 部分版块需登录 | 需要"需要登录"的空状态，且要能一键跳转登录 |
| 时间戳站点原样输出英文 | `24s ago` / `3h 27min ago` / `48min ago`。**设计稿请统一用中文**（"刚刚""3小时前"），这是客户端要做的本地化 |
| 当时 v1 只读（已过期） | 第一轮没有设计点赞/回复/收藏交互；后续画板已经补齐，真实写端点接入情况见实现状态文档 |

## 2. 目标与非目标

### 目标
1. **一眼认得出**：截图发到论坛里，别人能认出这是这个 app，而不是"某个 Material 模板"。
2. **刷得快**：一屏能扫到足够多的帖子，标题可读，元信息不抢戏。这是论坛客户端的核心指标。
3. **读得舒服**：帖子正文是长文中文阅读场景，排版质量决定这个 app 值不值得每天用。
4. **状态清楚**：加载、失败、需要验证、需要登录——每种都有明确、不吓人的界面。

### 非目标
- 不追求"信息流社交 app"的观感（不要大图卡片瀑布流）。
- 不做游戏化、成就、动画彩蛋堆砌。
- 不为大屏/平板做完整多栏布局（**但 tokens 与组件要能撑到 600dp+**，见第 8 节）。

## 3. 用户与场景

单一用户画像：**技术圈重度论坛用户**。

| 场景 | 频次 | 设计要点 |
|---|---|---|
| 排队/等电梯，30 秒扫一遍首页有没有新东西 | 每天 10+ 次 | 首屏信息密度、已读/未读区分 |
| 看到感兴趣的帖子，进去读完正文和前 20 楼 | 每天 5+ 次 | 正文排版、评论可读性、连续滚动不断层 |
| 找特定版块（交易 / 测评）看有没有捡漏 | 每天 2-3 次 | 版块切换要快，13 个版块横向 tab 不够用 |
| 收到回复通知，点进去看谁回了什么 | 每天若干 | 通知未读数、跳转到具体楼层 |

## 4. 设计方向（已确定）

- **视觉语言**：**Material 3 Expressive**（Google 2025 方向）。大圆角、形状变形动效、tonal 色块、
  强字重对比。但**长文阅读区域保持克制**——表现力用在导航、标签、状态、空态上，不要用在正文里。
- **主色**：不跟随壁纸动态取色。需要一套**属于这个 app 的品牌色**。
  参考起点：NodeSeek 网站的蓝 `#2D7FF9`。设计稿请给出完整的 light / dark 两套 M3 color scheme。
  （如果你有更好的种子色建议，请给 2-3 个方案对比，不要只给一个。）
- **列表形态**：**分割线密集列表**，不是卡片流。层次靠字重、tonal 版块标签、已读态、热帖标识拉开，
  不靠圆角和阴影。目标：**一屏 9-10 条**。
- **导航**：**底部导航栏**（M3 NavigationBar），4 个 tab。

## 5. 信息架构

```
底部导航（4 tab）
├── 首页        版块 tab 条 + 帖子列表 + 排序切换
├── 搜索        搜索框 + 最近搜索 + 结果列表
├── 通知        3 个分段：@我的 / 回复主题 / 私信          ← tab 上挂未读 badge
└── 我的        未登录态 / 已登录态（资料、收藏、我的主题、我的评论、签到、设置）

从首页/搜索/通知 → 帖子详情（全屏，非 tab 层级）
帖子详情 → 图片查看器（全屏沉浸）
登录/人机验证 → 受限内置浏览器；普通站外链接 → 系统浏览器
```

**后续修正**：通知实际只有三组；发帖、私信和签到主链路已接入。仍未接的评论、NodeImage 与
帖子互动写端点，以实现状态文档为准。

## 6. 屏幕清单

每屏都需要 **light + dark 两版**。标 ★ 的是优先级最高、必须先出的。

### 6.1 ★ 首页 / 帖子列表

**结构**
- 顶部 App Bar：app 名 / logo，右侧放搜索入口（如果底部已有搜索 tab，这里可以放排序或用户头像，请给方案）
- 版块 tab 条：横向可滚动。**13 个版块塞不下**，需要设计"全部版块"的展开方式
  （抽屉？bottom sheet？可编辑的常用版块？请给至少 2 个方案）
- 排序切换：站点支持"按发帖时间 / 按回复时间"两种排序，需要一个不占地方的切换入口
- 帖子列表：见 7.1
- 下拉刷新、滚动到底自动加载下一页（加载中指示器）

**必须覆盖的状态**
| 状态 | 说明 |
|---|---|
| 首次加载 | 建议用骨架屏而不是转圈——列表结构固定，骨架屏体感更快 |
| 加载更多 | 底部小转圈 |
| 空列表 | 少见但要有 |
| 网络失败 | 可重试 |
| **Cloudflare 人机验证** | 文案要说人话，主按钮"去验证"打开内置浏览器 |
| **需要登录** | 内版等版块未登录返回错误，主按钮"登录" |

### 6.2 ★ 帖子详情

**结构**
- 顶部 App Bar：返回、标题（单行省略）、更多操作（在网页中打开 / 分享 / 复制链接）
- 标题区：完整标题（可换行）、版块标签、浏览数
- 楼主区：头像、用户名、`楼主` 徽章、发帖时间、正文
- 分隔：楼主与评论之间要有明确的视觉断层
- 评论列表：见 7.2，翻页自动续接成一条长列表（用户感知不到分页）
- v2 预留：底部回复输入栏、每楼的点赞/回复动作条

**必须覆盖的状态**：加载中（骨架）、正文为空、评论为空（"还没有人回复"）、加载更多、失败、需登录

### 6.3 ★ 富文本正文规格

这是**和网页版拉开差距的核心**，请单独出一屏"正文排版规范"示例，把下列元素放在同一张图里：

| 元素 | 要求 |
|---|---|
| 正文段落 | 中文长文，字号 ≥16sp，行高 ≥1.65，段间距明确 |
| 行内表情（sticker） | 20sp 见方，与文字基线对齐，**不能撑高行高** |
| 独立图片 | 全宽、圆角、超高图片要限高并提示"点击查看全图" |
| 代码块 | 等宽字体、独立底色、**横向滚动不换行**、可选语言标签、复制按钮 |
| 引用块 | 左侧竖线 + 缩进 + 降低对比度 |
| 有序/无序列表 | 项目符号对齐 |
| 表格 | 横向滚动 |
| 行内链接 | 与正文可区分，但不要满屏蓝色 |
| 引用回复 | 正文常见 `@某人 #3` 开头，应作为可点击的引用标识而不是普通链接 |
| 分割线 | — |

**中文排版硬要求**：不使用斜体；不使用全大写；标题字重对比要够；避免过窄的行宽。

### 6.4 ★ 状态与空态合集

单独出一屏，把所有状态的插画/图标/文案风格统一：
加载中 · 空列表 · 网络错误 · 人机验证 · 需要登录 · 内容被删除 · 无搜索结果 · 未登录的"我的"

**文案原则**：说明发生了什么 + 给一个能点的动作。不要"出错了 :("。

### 6.5 搜索

搜索框（M3 SearchBar）、最近搜索（可删除）、结果列表（复用帖子列表项）、无结果态。

### 6.6 通知

3 个分段（@我的 / 回复主题 / 私信）。站点“系统通知”是私信中的置顶账号，不是第 4 个分段。
列表项：头像、谁、做了什么、内容摘录、时间、未读标识。
需要"全部已读"操作。

### 6.7 我的

- **未登录**：一个像样的引导页 + "登录"主按钮（打开内置浏览器）
- **已登录**：头像、用户名、等级、鸡腿/硬币数、注册时间；入口：我的主题 / 我的评论 / 我的收藏 / 签到 / 设置

### 6.8 设置

主题（跟随系统/浅色/深色）、正文字号、图片加载策略（始终/仅 Wi-Fi）、清除缓存、关于、开源许可。

### 6.9 图片查看器

全屏沉浸、双指缩放、下滑关闭、保存/分享、多图左右切换与页码。

### 6.10 内置浏览器

顶部：标题、关闭、刷新、在系统浏览器打开。加载进度条。
**用途**：登录、人机验证、打开站外链接。登录成功后要有明确的返回路径。

## 8. Design Tokens 交付要求

请给出完整的 token 表，**light 与 dark 各一套**，字段对齐 Material 3 的语义角色，
以便直接落到 Compose 的 `MaterialTheme`：

- **Color**：`primary` / `onPrimary` / `primaryContainer` / `onPrimaryContainer` / `secondary…` /
  `tertiary…` / `error…` / `surface` / `onSurface` / `onSurfaceVariant` /
  `surfaceContainerLowest…Highest` / `outline` / `outlineVariant`
- **Typography**：Display / Headline / Title / Body / Label 各 L/M/S。
  **额外**给出"正文阅读"专用样式（字号、行高、字间距），中文优先
- **Shape**：`extraSmall`(4) / `small`(8) / `medium`(12) / `large`(16) / `largeIncreased`(20) /
  `extraLarge`(28) / `full`
- **Spacing**：8dp 栅格
- **Elevation**：MD3 用 tonal surface 表达层级，**不要靠阴影**

**硬性要求**
- 正文文字与背景对比度 ≥ 4.5:1；次要文字（时间、计数）≥ 4.5:1（不要为了"高级感"用浅灰）
- 可点击区域 ≥ 48dp
- 字号跟随系统缩放，放大到 200% 时布局不能崩
- 深色模式不用纯黑（OLED 省电不是本项目目标，纯黑会让分割线消失）
- 布局用相对单位，600dp 以上不要把正文拉满宽（限制在 600-680dp 可读宽度）

## 9. 动效要求

克制但有存在感，重点在这几处：

| 位置 | 要求 |
|---|---|
| 列表 → 详情 | 共享轴转场，不要生硬切换 |
| 底部 tab 切换 | 图标形状/填充变化，M3 Expressive 的形状变形 |
| 下拉刷新 | M3 的 pull-to-refresh 指示器 |
| 骨架屏 → 内容 | 淡入，不要闪 |
| 图片查看器 | 从缩略图放大过渡，下滑关闭跟手 |
| 未读 badge | 出现时轻微弹性 |

**不要**：页面级视差、滚动触发的花哨动画、超过 500ms 的转场。
