## 0. 核对结论摘要

设计稿的页面骨架大多可用,但**数据与功能层有系统性偏差**,主要有八处:

1. **通知只有 3 个分组**(@我 / 回复主题 / 私信),没有"系统"分组;系统消息(投喂提醒等)
   是私信里一个置顶的"系统通知"账号会话,以 Markdown 消息形式发来。
2. **经济系统是鸡腿本位**:等级进度直接按鸡腿总数计(实测 344/400 → Lv2);签到得的是
   随机鸡腿(6–7 个/天)不是星辰;邀请码 1000 鸡腿一个。星辰是稀有货币,唯一来源是
   **评论被点赞(+1/次)**,唯一用途是**转账**(数额 + 收款人 UID + Ref ID)。
3. **关注/粉丝是半成品**:`/fans` 有"我的关注/我的粉丝"两个 Tab,但公开用户页上
   **没有关注按钮**(入口未找到)。不设计关系链社交,8b/8c 的关注按钮、互关状态全部砍掉。
   > **2026-08-02 修正**:这一条的后半句是错的,而且错在观察方法上——本次审计是在**未登录**
   > 状态下看的页面,站点的用户卡片正是用 `logined && !isMe` 决定要不要画关注按钮,所以它当时
   > 不在那儿。登录后按钮存在,走 `POST /api/fans/{add,del}`,关注状态是 `getInfo` 的 `followed`
   > 字段。8b 的关注按钮已按此重新加回;8c 仍不做行内关系态按钮,理由见 `FollowUser` 的注释。
4. **楼层互动是五件套**:点赞 / 加鸡腿 / 反对 / 引用 / 回复;**收藏只在楼主楼(#0)**;
   自己的楼"回复"变成"**编辑**"(无删除)。没有举报按钮。
5. **幸运抽奖不是转盘**:`/lucky` 是给帖子 T 楼抽奖用的**公证工具**(主题帖 ID / 开奖时间 /
   奖品数目 / 起始楼层 / 楼层去重 → 生成链接),不消耗任何货币。9c 整张作废。
6. **推荐阅读是加精帖列表**(`/award`,与首页同款列表 + 分页,现有 18 页),
   不是"每天 8 篇算法榜单"。
7. **搜索是三个入口**:搜帖子(`/search?q=`)、搜用户(`/member?q=`)、谷歌站内搜索。
   帖子结果页**没有排序和版块筛选 UI**(URL 支持单 category 参数);结果行含"最后回复人"。
8. **发帖编辑器**:阅读限制三档 = 公开 / Lv1 / 私有;图片走 NodeImage 集成;表情有五组
   (AC娘 / 洋葱头 / 小黄鸡 / Fluent / App);编辑器有 内容 / 预览 / **对照** 三种视图;
   "重要提醒"规则卡是全局常驻的,不是技术版专属。

## 1. 真实数据词典(设计时按此取样,不要再编造字段)

### 1.1 账户与资产(用户菜单实测)
| 项 | 真实值样例 | 页面 |
|---|---|---|
| 等级 | Lv 1 | `/progress` |
| 鸡腿 | 344 | `/credit` |
| 星辰 | 4 | `/stardust/list?member_id={uid}` |
| 通知 | 0 | `/notification` |
| 主题帖 / 评论数 | 5 / 96 | `/space/{uid}#/discussions` `#/comments` |
| 粉丝 / 收藏 | 0 / 0 | `/fans?type=fans` `/space/{uid}#/collections` |

用户菜单另有:发帖按钮、**签到图标**(无独立页)、**转账图标**(弹星辰转账层)、
设置、切换主题模式、**临时显示 Block 内容**开关、登出。

### 1.2 进度系统(`/progress`)
- 等级进度:`344 / 400`,Lv1 → Lv2,**进度值就是鸡腿数**。
- 四个每日额度条:今日发帖可得鸡腿 `0/20`;今日评论可得鸡腿 `3/20`;
  今日签到获得鸡腿 `7/7`(未签到/已签到两态);今日免费投喂额度 `0/0`(Lv1 为 0)。

### 1.3 鸡腿流水(`/credit`,表格 + hash 分页 #/p-N)
列:鸡腿变动 / 鸡腿总计 / 理由 / 时间。理由类型实测:`回帖奖励 +1`、
`签到收益N个鸡腿 +2~7`、`被{user}投喂鸡腿 +1`、`投喂鸡腿 -1`,
**外加 2026-07-30 补测到的第五类 `发帖奖励 +5`**(理由是站点自己的句子,不要在 App 里分类)。
分页每页 20 行,站点自己的页数上限是 100 页。

### 1.4 星辰流水与转账(`/stardust/list`)

> **2026-07-30 修正:本节原来的两句都是错的。** 契约取自站点分块
> `stardustList` / `stardustWrapper`,并对登录账号只读核对过;完整字段见
> 不提交的 `docs/private/api-notes.md`。

- 流水条目**不止点赞一种**:站点自己的文案映射有五类 —
  `点赞 / 转账 / 系统 / 管理 / 购买邀请码`,而且金额**可以为负**(转出、购码)。
  所以行必须带类型和符号,`+1` 写死是 bug。8e 画板按这个前提画的,已在实现里修正。
- 分页是**游标式**(`count` + `before_id` + `exist_more`),不是页码。
- 转账弹层字段不变:数额(number)/ 收款人 UID(number)/ Ref ID(正整数)→「发送星辰币」。
  没有备注这条仍然成立;**但"站点无 UID→昵称接口"不成立** —
  `POST /api/stardust/payment-prepare` 就会回 `receiver_name`,站点自己的确认弹层用的就是它。
  也就是说昵称回显不是 App 增强,而是照抄站点行为;转账整体也可以原生化。

### 1.5 通知与私信(`/notification`,hash 路由)
- 三分组:`#/atMe` @我、`#/reply` 回复主题、`#/message?mode=list` 私信;右上「全部标为已读」。
- 通知行文案:`{user} 在帖子 {title} 中@了我 · 2026/7/26 18:09:50`(带完整时间戳)。
- 私信列表行:用户名 + 最后一条摘要 + 时间;"系统通知"是一个普通会话置顶其中,
  内容如:`您的[评论](链接)被用户[iwil](链接)投喂鸡腿`(Markdown 渲染)。
- 会话页(`#/message?mode=talk&to={uid}`):标题「与{user}的对话」+ 返回;每条消息带
  时间戳与"编辑"标记(私信可编辑);输入区 = 多行文本 + **Markdown On/Off 开关** +
  发送按钮 + 完整 Markdown 工具栏。没有已送达/发送中状态展示(App 可自行做本地发送态)。

### 1.6 帖子详情
- 楼层操作:点赞 / 加鸡腿 / 反对(均带计数)/ 引用 / 回复;楼主楼(#0)多一个**收藏**(带计数);
  自己的楼是 点赞 / 加鸡腿 / 反对 / 引用 / **编辑**。无举报、无删除。
- 楼头:头像 / 用户名(管理员带"管理"徽章)/ 相对时间(title 为完整时间)/ `in 版块`(仅#0)/ #楼层号。
- 签名区显示在楼内容下方,支持 Markdown 链接(用户常放 博客/探针/私信 等自定义链接)。
- 页面底部是**常驻评论编辑器**(15 键工具栏:加粗/斜体/删除线/标题/无序/有序/引用/链接/
  图片/代码/表格/分割线/撤销/重做/清除格式 + 「发布评论」)。App 改为 FAB + Sheet 是
  我们的设计决策,保留 6a/6d 方案,但工具栏按键集合以这 15 键为上限参考。
- 数字分页(1…N)。

### 1.7 用户空间(`/space/{uid}`,hash Tab)
- 自己:概况 `#/general` / 主题帖 `#/discussions` / 评论 `#/comments` / 收藏 `#/collections`。
- 他人:概况 / 主题帖 / 评论(**无收藏 Tab**),头部唯一动作是**私信**按钮
  (链到 `/notification#/message?mode=talk&to={uid}`)。**没有关注按钮**。
- 概况统计:加入天数 / 等级 / 鸡腿数目 / 主题帖数 / 评论数目 + Bio 一句话 + Readme
  (无 readme 时显示"没有找到readme 🙄")。**没有**关注数/粉丝数/获赞/浏览量。

### 1.8 发帖(`/new-discussion`)
标题(请输入标题)/ 正文(内容 / 预览 / **对照** 三视图)/ 板块下拉(13 项,含内版、沙盒)/
阅读限制下拉(公开 / Lv1 / 私有)/「发布帖子」。编辑器提示"支持markdown语法 ·
NodeImage已就绪 · 鼓励友善发言";表情面板五组:AC娘 / 洋葱头 / 小黄鸡 / Fluent / App。
右侧常驻「重要提醒」卡:敏感话题发内版、发卡站/大量出售必须发推广、禁止人身攻击、违规惩罚。

### 1.9 搜索
- 搜索框下拉三选:search for post / search for people / use google search。
- 帖子结果(`/search?q=`):与首页同构的密集行(标题/作者/浏览/回复/**最后回复人**/时间/版块)
  + 数字分页;无排序、无版块筛选 UI。
- 用户搜索是独立页(`/member?q=`)。App 把两者做成 Tab(6e–6h)是合理封装,保留;
  版块多选是 App 端本地过滤,需在稿上标注"服务端仅支持单版块"。
