## 1. 产品定位与设计目标

NodeSeek 是高频、信息密集的中文技术论坛。用户常在排队、通勤、等服务器任务时快速扫帖，也会连续阅读几十层评论。新版客户端要做到：

1. **扫得快**：360×800 dp 首屏优先展示标题、版块、最后活跃、回复变化；不要用大图卡片瀑布流。
2. **读得稳**：长文、代码、表格、图片和引用在单一连续滚动中保持节奏。
3. **写得顺**：手机键盘、图片、表情、引用楼层和草稿恢复都要考虑。
4. **状态可信**：离线缓存、Cloudflare、人机验证、需登录、权限不足、内容删除必须一眼可懂。
5. **有品牌记忆**：Material 3 Expressive 的颜色、形状、tonal 层级和适度弹性动效要成为 NodeSeek 的识别点，而不是套用默认 Material 模板。

## 3. 信息架构与主导航

主导航保持 4 项：**首页 / 搜索 / 通知 / 我的**。手机使用底部 NavigationBar；600 dp 以上切换 NavigationRail。帖子详情、编辑器、图片查看器、私信会话、WebView 为全屏二级页面，不显示底部导航。

首页顶部提供「新评论 / 新帖子」模式切换；版块用横向 chip + “全部版块” bottom sheet，支持最近使用/收藏版块置顶。发帖使用首页右下 FAB；从详情底部固定回复入口进入编辑器。通知 tab 显示未读 badge，进入通知后可直接跳到帖子楼层或私信会话。

### 3.1 帖子详情的操作层级

详情页是子级内容页，隐藏首页底部 NavigationBar，底部空间只服务于阅读和回复。必须遵守“一个页面只有一个最高强调操作”的层级：

- **回复主题**是唯一主操作，浏览状态使用 Extended FAB（图标 + “回复”），采用主色或高对比 `primaryContainer`，不使用永久空输入框。
- **上一页 / 下一页**是阅读导航，不做普通文字 Button；使用低强调圆形 `IconButton`，放在 `surfaceContainer` 的 Floating Toolbar 中。
- **当前页 / 楼层信息**是工具栏信息按钮，不是主按钮。显示格式根据真实数据动态决定：分页可用时显示“第 X / Y 页”；自动续页时优先显示“已载入楼层 / 总楼层”或“到最新”，总量未知时不伪造数字。
- **跳页 / 跳楼 / 上次阅读 / 到最新**属于低频动作，点击页码或楼层信息后打开 Bottom Sheet；不要在手机底部横向铺开一串页码。

推荐的展开态是“Floating Toolbar + Attached FAB”：

```text
╭──────────────────────╮  ╭────────────╮
│ ‹   第 X / Y 页⌄   ›  │  │ ↩  回复    │
╰──────────────────────╯  ╰────────────╯
```

工具栏使用低强调 tonal surface，回复 FAB 更高、更亮或更具 Expressive 形状。开始阅读或向上滚动时显示完整工具栏；持续向下阅读时收起分页工具，只保留回复 FAB；到达分页边界、自动加载失败或用户主动请求导航时重新展开。展开/收起应使用短促弹簧动效，不能遮住正文关键内容。

点击回复后，底部区域发生状态转换：分页工具和 FAB 暂时隐藏，改为回复编辑器。短回复可用 Modal Bottom Sheet；支持 Markdown、图片、表情和预览时进入全屏编辑页；回复指定楼层时，编辑器标题显示“回复 #实际楼层”。禁止同时显示回复 FAB、空回复栏和分页工具。

楼层内的“回复”是局部操作，不应与主题回复同级：放在楼层底部的低强调 `TextButton` 或 `IconButton`，旁边可放更多菜单。点击后复用同一个编辑器，并带入“回复 #楼层 · 用户名”的上下文。引用跳转、点赞、反对、加鸡腿、收藏也属于楼层或帖子局部操作，不得抢过主题回复的视觉权重。

页码 Bottom Sheet 至少包含当前实际页/总页、可输入的页码、第一页、上次阅读、最后一页和“前往”。若服务端总页数或总楼层尚未返回，使用加载态或“总数未知”，不要把设计稿中的示例数字当成固定产品字段。

### 3.2 搜索的目标、范围与历史

搜索页不把“帖子 / 用户 / 全部版块 / 指定版块 / 历史记录”做成同一排按钮。三者职责必须分开：**帖子或用户决定搜什么；版块决定帖子去哪里搜；历史记录负责重复完整搜索**。

- 顶部使用持久显示的 M3 `SearchBar`。输入后可展开为全屏搜索视图，尾部只保留清除 `×`，不额外放一个大“搜索”按钮；使用键盘 Search、建议项或历史项提交。
- “帖子 / 用户”使用 `PrimaryTabRow`，默认帖子。切换时保留关键词，并分别保存两个 Tab 的结果和滚动位置；切到用户时隐藏版块筛选，placeholder 改为“搜索用户名”。不要使用两个 FilterChip，它们是不同数据集而不是筛选条件。
- 帖子 Tab 只放一个范围摘要 `FilterChip`：`全部版块`、`开发 +2` 或 `已选 3 个版块`。具体选择进入 `ModalBottomSheet`，顶部用“全部版块 / 指定版块”单选分段，指定版块使用 Checkbox 多选；底部固定“重置 / 应用 N 个版块”。版块较多时提供“查找版块”，并优先展示最近使用版块。
- 搜索历史使用两行 `ListItem`，不要做成一排关键词胶囊。第一行是关键词，第二行说明“帖子 · 全部版块”或“帖子 · 技术、交易”，用户搜索则显示“用户”。整行重用原条件搜索，右侧 `×` 只删除单条，“清除”清空当前 Tab。相同关键词但范围不同必须是不同历史记录；相同关键词和范围再次搜索只更新时间并移到顶部。
- 帖子结果复用普通 `PostRow` 的密集列表，只增加关键词高亮、范围摘要、相关度/时间排序入口；用户结果使用头像 + 两行 `ListItem`（用户名、UID/等级/签名），点击进入用户页，用户 Tab 不出现版块 Chip。
- 空状态要按上下文区分：尚未输入、帖子无结果、用户无结果、离线无法远程搜索。帖子无结果可提供“搜索全部版块”，用户无结果只提示检查用户名，不能显示无关的版块建议。

搜索页的 Expressive 表现放在状态变化而非装饰堆叠：SearchBar 胶囊展开为全屏搜索视图； Tab 指示器平滑移动但 SearchBar 不位移；范围 Chip 的勾选、文案和宽度平滑变化；Bottom Sheet 应用后返回并更新范围摘要。搜索结果仍然像论坛帖子列表，不另造大卡片流。

## 4. 必须设计的页面与状态

### P0：先出稿并做可点击流程

- 首页帖子流：首次骨架、下拉刷新、追加加载、离线缓存、网络失败、Cloudflare、需登录、空列表；密集分割线列表，标题最多两行。
- 帖子详情：楼主卡、连续评论、楼层跳转、长文富文本、代码/表格/图片/引用；按 3.1 的单一主操作层级设计 Floating Toolbar + Attached FAB；互动 action sheet（点赞、反对、加鸡腿、收藏、分享）；评论编辑器（引用、@、表情、图片、草稿、发布中/失败）。
- 发帖编辑器：标题、正文、版块、阅读权限、Markdown 工具栏、预览、图片上传、草稿恢复、发布确认和规则提醒。
- 全站搜索：帖子/用户 Tab、搜索建议、帖子版块范围、远程结果、排序/分页、分层历史、无结果和离线回退。
- 通知与私信：@我/回复/系统/私信分组、未读/已读、全部已读；私信列表、会话气泡、Markdown 开关、发送失败重试。
- 登录与验证：登录、人机验证、权限不足、Cookie 成功自动返回、取消/失败。

### P1：第二批

- 我的：登录/未登录、个人概况、我的主题、评论、收藏；公开用户页、私信、关注/粉丝。
- 资产成长：等级进度、签到、鸡腿流水、星辰流水/转账、邀请码购买；所有扣款操作必须二次确认。
- 账号设置：个人信息、头像、Bio/签名/Readme、安全/密码/2FA、联系方式、屏蔽用户、首页版块偏好。
- 图片查看器：多图、缩放、保存、分享、下滑关闭。

### P2：更多入口

推荐阅读、幸运抽奖、邀请好友、管理记录、合作商家、友站链接。设计为“更多/社区工具”列表，不进入四项主导航。

## 5. M3 Expressive 视觉约束

- 使用完整 light/dark `MaterialTheme` token；现有品牌基线是石墨青 `#35606E`，请在稿中给出 2 个替代种子色对比后定稿。
- 表现力集中在导航选中态、版块 chip、状态页、FAB、资产卡和形状变形；正文阅读区保持克制。
- 允许异形组件：不对称圆角、连接按钮、切角/波浪 tonal 容器，但不能破坏 48 dp 点击区、文字基线和列表扫描。
- 颜色用版块分组而非 13 色乱跳：日常/技术/情报/交易等最多 4 个色族；选中态用填充与形状，不只改颜色。
- 不用纯黑；正文和次要信息对比度至少 4.5:1；字号跟随系统，200% 字号不溢出。
- 8 dp 栅格；正文可读宽度 600–680 dp；阴影少用，优先 tonal surface 表达层级。
- 动效使用弹簧/共享轴：列表→详情、导航选中、骨架→内容、图片查看器；单次转场不超过 500 ms，禁止页面级视差。
- 详情页工具栏遵循“展开 → 收起 → 边界再展开”的滚动状态；回复 FAB 到编辑器是同一底部区域的状态转换，不做两个组件交叉淡入造成重复操作。

## 6. Open-design 交付清单

1. 完整 light/dark 色彩、字阶、形状、间距、动效 token。
2. P0 六条主流程的 360×800 dp 页面与关键状态；至少补一张 600 dp 适配示意。
3. 组件状态页：帖子行、评论行、互动条、编辑器、通知行、私信气泡、搜索栏、帖子/用户 Tab、版块范围 Chip、版块选择 Bottom Sheet、搜索历史 ListItem、搜索结果行、状态页、资产卡、异形 FAB。
4. 每张稿标注：现有功能 / 新增功能、数据缺失时的回退、登录/离线/错误状态、可点击区域和无障碍标签。
5. 用真实中文样本，不使用 Lorem ipsum；正文样本覆盖长标题、短评论、代码、表格、图片、@引用和表情。

## 7. 验收标准

用户能在 3 秒内从首页辨认未读/新回复；从通知跳到正确楼层不丢上下文；从帖子开始回复、插入引用并发布；在搜索中切换帖子/用户、复用带版块范围的历史条件，并找到未缓存帖子；在离线、未登录、Cloudflare 和权限不足时知道下一步做什么。设计稿必须能映射到现有 Compose 路由，并为 P0 的 Repository/ViewModel 写操作预留明确状态，不以“打开网页”作为默认交互。
